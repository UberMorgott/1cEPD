## Задача

Веб-интерфейс `web/` приведён к виду референса **https://dashboard-vue-template.nuxt.dev/**
(Nuxt UI Pro dashboard, тёмная тема). Приложение переименовано в «Пульт ЭПД» везде (логин,
сайдбар, заголовок страницы). Экран «Реестр» упразднён — данные влиты в «Биллинг» (одна таблица,
строки соединены по `edoId`; записи, присутствующие в накопительном реестре, но отсутствующие в
последнем снимке, остаются видимыми с тегом «нет в снимке» и прочерком в денежных колонках).
Маршрут `/identifiers` редиректит на `/billing`; `web/src/views/IdentifiersView.vue` удалён.

Экран «Заявки» хранит историю: «Сохранить» отправляет форму, повторное сохранение обновляет ту же
строку по id и ревизии; таблица истории (название, статус, ревизия, изменена, выгружена); «Открыть»
загружает в форму, «Скачать» пересобирает .xls по id; 409 при устаревшей ревизии предупреждает
пользователя.

Заявка теперь и отправляется из сервиса: `POST /api/its/send` собирает тот же файл, что «Скачать»,
и уходит письмом с вложением; отметка об отправке — колонка `sent_at` в `its_requests`, статуса
`sent` нет. Почта настраивается на экране «Настройки» (`/settings`, `GET`/`PUT /api/settings`,
`POST /api/settings/smtp/test`): SMTP-хост, порт `465` (сразу TLS) или `587` (STARTTLS), логин,
пароль приложения, адрес отправителя, список получателей — по умолчанию `itsrobot@1c.ru`.
Пароль наружу не отдаётся никогда: в ответе только флаг `smtpPasswordSet`, запись односторонняя
(поля нет — оставить, `null` — удалить, `""` — отказ), в базе он зашифрован AES-256-GCM ключом
из файла `secret.key` рядом с базой (создаётся при первом старте, переносится вместе с базой).
Отправщик — `internal/mailer` на stdlib `net/smtp`, ошибку SMTP пользователь видит как есть.

Перед сборкой файла и перед отправкой заявка проверяется в 1С: регномер заведён в Личном кабинете
клиента (`client-program-access/search/reg-number`), идентификатор ЭДО связан с логином
(`edo/reports/client-traffic` за год). Блокирует только определённый отрицательный ответ;
недоступность 1С даёт отметку «не проверено» и выпуск не останавливает.

Вход: блокировка по адресу клиента осталась (5 неудач за 5 минут → `429`), блокировка по логину
заменена растущей задержкой ответа `2^(N-1)` с с потолком 30 с — учётная запись общая, и запирать
по логину значило бы запирать вход всем сразу. При входе меняется идентификатор сессии,
cookie `SameSite=Strict`, на небезопасных методах проверяется `Sec-Fetch-Site`, CSP без внешних
источников, файл базы `0600`. Пароль входа можно писать в `.env` открытым как `APP_PASSWORD`;
`APP_PASSWORD_HASH` работает по-прежнему и побеждает, если заданы оба.

Подключён quality gate (`qgate`): lefthook pre-commit, eslint + stylelint, `.golangci.yml`,
govulncheck. Go-тулчейн обновлён до 1.27.1, x/crypto v0.56.0 (закрыты четыре уязвимости stdlib).

## Как запускать и проверять

Полная проверка:

```powershell
Set-Location E:\DEV\1сEPD; & "E:\DEV\quality-gate\bin\qgate.ps1" -All -Full
```

Exit 0 — всё зелёное. Gate запускает: для Go — gofmt, go build, go vet, golangci-lint, go test,
go test -race, govulncheck; для web — stylelint, eslint, vue-tsc type-check, vite build, npm audit.
Lefthook pre-commit
запускает то же самое на каждом коммите.

Сборка фронта:

```powershell
Set-Location E:\DEV\1сEPD\web; npm run build
```

Фронт встроен в бинарь через `go:embed all:dist`, поэтому `web/dist/` **коммитится** и без
`npm run build` перезапуск ничего не поменяет.

Сервер (`go run`, слушает 127.0.0.1:8123) перезапускается так: убить процесс, слушающий 8123,
вместе с родительским `go.exe`, затем

```powershell
Start-Process -FilePath "go" -ArgumentList "run",".\cmd\server" -WorkingDirectory . -WindowStyle Hidden
```

После обновления Go-тулчейна golangci-lint и govulncheck надо переустановить:

```powershell
go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@latest
go install golang.org/x/vuln/cmd/govulncheck@latest
```

Визуальную проверку делает пользователь: **пароль в форму я не ввожу** (запрещено), логин он
называет сам. Встроенный браузер — `mcp__Claude_Browser__*`, приложение открывать новой вкладкой
(`tabs_create`), вкладка `seed` привязана к локальному предпросмотру и не навигируется.

## Как работаем с Codex

```powershell
cx -PromptFile "<абсолютный путь к промпту>" -WorkDir "E:\DEV\1сEPD" -Deep -Search
```

Возвращает одну строку, ответ кладёт в `C:\Temp\cx\<guid>.out.md` (каталог временный, отчёты могут
исчезнуть). Отчёт **не читать в основной контекст** — отдать агенту `scout` с задачей сверить каждую
находку с текущим кодом, отбросить устаревшее и вернуть не больше 15 строк вида
`file:line — что не так — точное значение замены`. Промпты прошлых заходов лежали в скрэтчпаде
сессии; при необходимости пересобрать из раздела «Токены референса» выше.
