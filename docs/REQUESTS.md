# Файл-заявка на регистрацию 1С:ИТС и сервисов — правила

Источники: «Справочник партнёра по ИТС» (`its.1c.ru/db/partnerits`), инфовыпуск «1С» № 34677
от 17.07.2026, шаблон формы вер. 3.09.

Через API заявку подать нельзя — только файлом на почту. См. [API.md](API.md), §10.

---

## 1. Как это работает

1. Партнёр заполняет файл Excel по шаблону.
2. Отправляет на **`itsrobot@1c.ru`**. Других способов нет. В «Пульте ЭПД» это делает кнопка
   «Отправить»: письмо уходит с почтового ящика, заданного на экране «Настройки», получатели —
   оттуда же, по умолчанию тот же `itsrobot@1c.ru`.
3. Робот отвечает протоколом обработки с адреса `autoits@1c.ru` на e-mail, указанный в шапке заявки.
4. Партнёрам, работающим напрямую, счёт приходит на следующий день после регистрации, туда же.
   Счета за сервисы — по итогам месяца.
5. Если в заявке ошибка — исправить и отправить повторно на тот же адрес.

Куда писать людям, а не роботу:

| Адрес | Зачем |
|---|---|
| `itsrobot@1c.ru` | отправка заявки (только автоматика) |
| `autoits@1c.ru` | отсюда приходит протокол, писать туда не нужно |
| `its-dostavka@1c.ru` | продублировать или исправить счёт |
| `its@1c.ru` | корректировка заявок на сервисы |
| `epd@1c.ru` | индивидуальный тариф ЭПД от 200 000 документов в год |
| `zakaz-its@example.ru` | вопросы по оформлению (отдел ИТС) |

**Имя файла:** `ip<первые 5 цифр кода партнёра>.xls`. Для кода 00000 — `ip00000.xls`.
Файл `ip00000_ru.xls` — это пустой шаблон, а не имя для отправки.

## 2. Жёсткие запреты

- **Менять структуру файла нельзя**: ни наименования полей, ни их расположение.
  Заполняется существующий шаблон, а не создаётся похожий файл.
- Произвольно или некорректно заполненные заявки не регистрируются.
- Отказ от ИТС регистрируется только со следующего месяца или выпуска, задним числом нельзя.
- Заявка на продление **не меняет** контактные данные, ИНН и КПП. Для этого отдельная заявка
  с видом 1С:ИТС `50` (корректировка контактной информации).
- Сервисы «1С:Предприятие через Интернет» (Фреш) подключаются в Менеджере сервиса,
  а не файлом-заявкой.

Количество строк в одном файле не ограничено.

## 3. Шапка «Информация об отправителе заявки»

| Поле | Тип, длина | Обяз. | Что писать |
|---|---|---|---|
| Код партнера | 5 символов | да | первые 5 цифр учётного кода партнёра |
| Ответственный | до 50 | нет | ФИО отправляющего сотрудника |
| e-Mail | до 80 | да | сюда придут протокол и счёт |
| Пароль | 5–20 латинских букв и цифр | нет | пароль подтверждения подлинности заявки |
| Новый пароль | 5–20 латинских букв и цифр | нет | смена пароля |
| Заказать сводный отчёт 1С:ИТС | 1 символ | нет | пробел — не присылать, `1` — прислать (оплаты и отгрузки) |
| Заказать детальный отчёт 1С:ИТС | 1 символ | нет | пробел — не присылать, `1` — прислать отчёт пользователя |

**Про пароль.** Это **не** пароль от портала и не пароль от API. Отдельный пароль авторизации
доступа к данным о зарегистрированных договорах, служит подтверждением подлинности заявки.
По умолчанию пустой, можно вообще не назначать.
Чтобы назначить впервые — «Пароль» оставить пустым, новый вписать в «Новый пароль».
Чтобы сменить — старый в «Пароль», новый в «Новый пароль».

## 5. Справочники

**Операция:** `0` — новый договор или продление, `1` — отказ от помесячного либо льготного договора.

**Способ получения:** `0` — самовывоз, `1` — через дистрибьютора.

**Способ оплаты:** `0` — помесячно, `1` — предоплата за весь срок.

**Причины отказа:**

| Код | Причина |
|---|---|
| 1 | прерывание договора на период по финансовым причинам клиента |
| 2 | партнёр не планирует работать с клиентом |
| 3 | клиент хочет использовать конфигурацию без сопровождения, обновлений и сервисов |
| 4 | фирма ликвидирована |
| 5 | договор зарегистрирован партнёром ошибочно |

**Виды 1С:ИТС** — около 250 кодов, полный список на листе «Коды ИТС_сервисов» в самом шаблоне
(449 строк). Ориентиры по группам:

| Диапазон | Что это |
|---|---|
| `50` | корректировка контактной информации |
| `51`–`53` | апгрейды |
| `61`, `62`, `69`, `75`, `76` | ИТС Международный |
| `77`–`80` | схемы 8+4 |
| `125` | СтартЭДО |
| `135`–`138` | 1С:Контрагент |
| `160`–`166`, `2001`–`2065` | 1С:КП |
| `230`, `233`, `235`, `237` | 1СПАРК Риски |
| `260`, `263`, `2630`–`2653` | 1С:Подпись |
| `361`–`378` | Облачный архив, 1С:Линк |
| `1000`–`1034` | ИТС Ритейл |
| `2080`–`2085`, `2092`–`2096`, `2840`, `2841` | 1С-ЭДО ЭПД, см. §6 |
| `2150`–`2189` | распознавание первичных документов |
| `2500`–`2531` | 1С-ЭДО годовые пакеты, от 200 до 600 000 документов |

## 6. Тарифы 1С-ЭПД

Отдельный раздел, потому что правила жёстче общих и по ним идут продажи.

### Коды для поля «Вид 1С:ИТС»

| Код | Тариф | Код | Тариф |
|---|---|---|---|
| 2092 | ЭПД-200 | 2096 | ЭПД-7000 |
| 2080 | ЭПД-600 | 2083 | ЭПД-10000 |
| 2081 | ЭПД-1000 | 2840 | ЭПД-20000 |
| 2093 | ЭПД-2000 | 2841 | ЭПД-30000 |
| 2094 | ЭПД-3000 | 2084 | ЭПД-50000 |
| 2095 | ЭПД-4000 | 2085 | ЭПД-100000 |
| 2082 | ЭПД-5000 | | |

**Расхождение источников.** «Справочник партнёра» перечисляет только `2080`–`2085` — шесть
старых тарифов. Семь остальных (`2092`, `2093`, `2094`, `2095`, `2096`, `2840`, `2841`) введены
инфовыпуском № 34677 от 17.07.2026, справочник на момент проверки их не содержит.
Источник истины — инфовыпуск.

### Обязательные значения

- «Наименование фирмы», «ИНН» и «КПП» — заполняются обязательно (общее правило делает ИНН
  необязательным, для ЭПД он обязателен);
- «Количество выпусков» — строго `12`;
- «Способ оплаты» — только `1`, помесячная оплата не допускается;
- «Дата начала» — формат `ДД.ММ.ГГ`;
- отказы не допускаются.

### Что проверить до отправки

1. Регистрационный номер программы зарегистрирован в Личном кабинете клиента на Портале ИТС.
2. Идентификатор участника ЭДО связан с логином того Личного кабинета, на который
   регистрируется тариф.
3. В Кабинете партнёра настроена связь с этим клиентом по ЭДО.

Первые два пункта сервис проверяет через API сам — при проверке заявки, перед сборкой файла
и перед отправкой. Блокирует выпуск только определённый отрицательный ответ: регномера нет
в Личном кабинете, идентификатор ЭДО связан с другим логином. Если 1С не ответила или проверять
нечем, пункт помечается «не проверено» и выпуск не блокирует — недоступность API заявку
плохой не делает.

### Локальные программы против Фреша

Льготный лимит тарифа, оформленного файлом-заявкой, действует **только** на организации,
у которых код абонента-владельца идентификатора ЭДО начинается на `CL-` — то есть клиент
работает в локальной программе.

Для клиентов в облаке Фреш (код владельца на `FR-`) тариф оформляется **не заявкой**, а подпиской
в «Менеджере сервиса», папка «1С-ЭДО», и коды там другие:

| Код | Тариф | Код | Тариф |
|---|---|---|---|
| 1223 | ЭПД-200 | 1227 | ЭПД-7000 |
| 1200 | ЭПД-600 | 1203 | ЭПД-10000 |
| 1201 | ЭПД-1000 | 1228 | ЭПД-20000 |
| 1224 | ЭПД-2000 | 1229 | ЭПД-30000 |
| 1225 | ЭПД-3000 | 1204 | ЭПД-50000 |
| 1226 | ЭПД-4000 | 1205 | ЭПД-100000 |

При оформлении через Менеджер сервиса лимит доступен сразу после оформления подписки.

Заявка на клиента с владельцем `FR-` уйдёт в брак. Это самая дорогая ошибка в теме,
и она проверяется автоматически: код абонента виден в отчёте биллинга ЭДО.

## 7. Что автоматизируется

| Шаг | Автоматика |
|---|---|
| Реквизиты клиента (наименование, ИНН, КПП) | из API по коду абонента или логину |
| Регистрационные номера | из API |
| Вид 1С:ИТС | выбор из справочника с поиском, для ЭПД — только 13 кодов |
| Количество выпусков, способ оплаты | подставляются принудительно для ЭПД |
| Формат даты начала | подставляется по виду услуги |
| Проверка `CL-` против `FR-` | по коду абонента-владельца из отчёта биллинга |
| Проверка связи идентификатора с логином | из отчёта трафика ЭДО |
| Проверка регномера в ЛК клиента | поиск по регномеру в партнёрском API |
| Заполнение файла | по шаблону, структура не меняется |
| Отправка | письмом по SMTP на адреса из «Настроек», по умолчанию `itsrobot@1c.ru` |

## 8. Формат файла

Строго `.xls` (BIFF8) — тот же формат, что у шаблона `ip00000_ru.xls` вер. 3.09. `.xlsx` не подходит.

Готовых Go-библиотек, которые пишут BIFF8 с сохранением оформления, нет (`excelize` работает
только с `.xlsx`). Поэтому шаблон правит пакет `internal/xlsfill` на уровне записей BIFF8, прямо
в процессе сервиса: меняются только ячейки заявки, каждая сохраняет XF шаблона (формат «Текст»,
рамки, шрифт), новые строки дописываются в таблицу SST, сдвинутые смещения пересчитываются.
Остальные записи, включая стили и справочник, переносятся байт в байт. Внешних утилит, Python
и LibreOffice на сервере не нужно.

Перед вводом в работу обязательно отправить одну настоящую заявку на `itsrobot@1c.ru` и дождаться
протокола с `autoits@1c.ru`: робот отвергает файлы с изменённой структурой, а заполнение шаблона
теряет часть оформления и может незаметно что-то поменять.
